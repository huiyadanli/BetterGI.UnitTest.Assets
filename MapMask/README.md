# 地图遮罩回归样本

本目录属于 `BetterGI.UnitTest.Assets` 资源仓库，统一保存 37 张真实截图和 12 份坐标 JSON。对应测试代码位于主仓库 `Test/BetterGenshinImpact.UnitTest/GameTaskTests/MapMaskTests`。

测试前在主仓库根目录执行 `git submodule update --init -- Test/BetterGenshinImpact.UnitTest/Assets`，再编译测试项目；WebP 和 JSON 会一起复制到输出目录 `TestData/MapMask`。更新资源时保留与测试用例一致的文件名，并先提交、推送资源，再更新主仓库的子模块指针。

独立地图样本来自 `Captures` 下 2026-11-15 的 08:56:52、08:56:58、08:57:14（渊下宫）和 09:25:18、09:25:22、09:25:26、09:25:37（霜月）。右下角 UID 在缩放前遮盖；`moon-highland-4k` 保留原始分辨率。`IndependentMapTests` 使用实际 CPU OCR 读取场景标题，再进入同一 L3/L4/L5 匹配流程；覆盖远近缩放、不同岛屿、海域、场景往返及详情遮挡，也直接验证 L3 不依赖 SIFT。

`enkanomiya-yachimatahime` / `enkanomiya-yachimatahime-4k` 来自用户新增的 `原神 2026_11_15 17_17_02.png`，分别保留 960×540 和原始 3840×2160 分辨率，仅遮盖右下 UID。八衢姬之地视口中心约为游戏坐标 `(-707, 1200)`、宽度约 `1201`；期望来自完整官方底图的独立地形配准，未使用生产匹配输出生成。截图只有一个传送锚点，必须由 L4 定位并报告地表楼层，不能让 L3 伪造多点结果。原 1.0.26 的渊下宫底图缺少外围岛屿，需要包含资源修复的地图包（当前本地验证版 `1.0.26-enkanomiya.1`，尚未发布）。

`web-anchors-*.json` 与 `tavern-anchors-*.json` 只保留网页 X/Y 和离线传送点的游戏 X/Y 四个数值。数据分别来自官方地图 map_id=7/9/34/36/37/40 及酒馆地区 15/4/32/48/55/56，与仓库 `tp.json` 的位置平面对齐，用于检验各独立地图的比例和原点；手工标点与实际落点允许小幅误差。测试不联网。`IndependentMapPointServiceTests` 另通过实际点位服务校验请求地图、缓存隔离、详情地图和场景图像投影。

并行分支的结果发布与资源回收分别验证：`BigMapParallelStagesTests` 用任务门模拟无法立即取消的原生调用，要求坐标先发布、帧资源直到慢分支退出仍可读取；地下先发布未知楼层的坐标，再由 L5 升级，地图移动后禁止发布迟到楼层。`BigMapCascadeMatcherTests` 使用矿区 4K 遮挡及传送详情截图校验所有提前发布的坐标和楼层语义。共享 SIFT 由已有分支直接提取，另一个分支异步等待；诊断分别记录分支排队、阶段执行、结果就绪与后台收尾耗时。

`BigMapMotionTrackerTests` 在真实地图上构造连续平移、缩放并保留固定 UI，要求每帧视口都符合已知变换，覆盖 4K 日志遮挡及详情面板；另验证跟踪丢失、切图及旧修订拒绝。该轻量路径直接驱动拖动中的点位，全局 L3～L5 搜索负责稳定后的绝对校准。`MaskWindowMapStateTests` 同时校验 UI 端计时：截图到 UI 的延迟包含排队和刷新等待，本次重定位耗时还包含稳定等待、取消回收和重试，不能与单个匹配函数耗时混用。

`MapMaskDispatchTests` 直接覆盖调度器的界面过滤入口：地图保持 31 秒、5 分钟或 1 小时后仍持续投递截图，同时验证主界面小地图、关图清理及其他触发器原有的界面过滤。仅验证匹配器无法发现稳定界面超过 30 秒后停止调度的问题。

样本为原神真实地图截图，大地图默认以 960×540 无损 WebP 保存，小地图样本使用 1920×1080，均遮盖右下角 UID；`*-4k` 保留 3840×2160 原始分辨率。测试必须读取仓库样本；缺失文件或识别失败会明确失败，不使用个人目录、不静默跳过。

- `city-*`：2026-11-14 已有的六张截图，覆盖新基捷城地表、地下第一层、第二层、平移及缩放。`city-b1-east` 选中的是克什尼克矿区，虽然同属第一层且视口未变，也必须切换层名，不能沿用城市层。
- `minimap-city` / `minimap-city-4k`：用户 `原神 2026_11_15 20_14_12.png` 的小地图点位错位截图，分别保留 1920×1080 和原始 3840×2160，UID 在缩放前遮盖。独立 SIFT 地形配准有 137 个一致内点，确定成功层为新基捷城地下第一层 `LayeredMap_29_-1`（Scale=3），原生图像中心约 `(24356.2, 4730.1)`、完整小地图宽约 `235.5`；期望不来自生产定位输出。`MiniMapViewportTests` 经过生产截图归一化和导航定位入口，验证冷启动、后续局部匹配及最终视口范围，防止定位正确却因忽略层比例而将范围扩大三倍。
- `station-*`：本次从运行中的原神采集的四张截图，覆盖已遭废弃的列车站所在区域地表、两个地下按钮和第二层放大视图。采集仅操作地图 UI，没有运行 BetterGI。
- `mine-b1-failure` / `mine-b1-failure-4k`：用户反馈仍然失败的 2026-11-15 03:58:23 截图。克什尼克矿区第一层，视口中心约 (3678, 9965)、2048 级宽度约 6257；同时保存缩略图和原始 4K，覆盖小缩放外观核验、冷启动、地表切地下和连续帧。
- `city-waypoint-popup` / `city-waypoint-popup-4k`：用户 06:13:44 的传送锚点详情面板截图。中心约 (4314, 9988)、宽度约 5778，当前层为新基捷城。面板遮住右侧约 25.6%，按钮列随之左移，但输出坐标仍按完整屏幕计算。
- `city-b1-wide-new` / `city-b1-close-new` / `city-b1-mid-new` / `city-b1-zoom-new`：用户 06:15:33～06:16:20 新增失败截图，覆盖最宽视口与多个近距离缩放。验证徽记和背景变化不影响蓝色选中按钮；中等缩放不能被只露出暗色公共背景的“矿洞深底”抢先命中。
- `mine-marker-popup`：从原神采集的“标记/确认”面板截图，中心约 (3678, 9965)、宽度约 6303，当前层为克什尼克矿区。验证任意位置弹框及关闭弹框后继续匹配。
- `mine-runtime-overlay` / `mine-runtime-overlay-4k`：用户 06:36:23 的实际运行失败截图，保留 BetterGI 日志、定位诊断和 Game Bar 提示遮挡，仅遮盖 UID。中心约 (3902, 10005)、宽度约 4733，选中克什尼克矿区第一层。冷启动不能靠数十帧轮转才命中，缩略图和原始 4K 均要求第一次 Match 返回正确坐标及层名。
- `inazuma-surface` / `inazuma-zoom` / `inazuma-zoom-near` / `inazuma-zoom-far`：从正在运行的原神采集的稻妻视口，中心约 (-3225, -4016)，2048 级宽度分别约 5759 / 3496 / 1640 / 9854。通过拖动缩放滑块采集，并恢复原来的缩放；覆盖普通比例、较近、最大放大与最大缩小。只有锚点足够时走 L3，其余视图正常回退 L4。

`LayerButtonGeometryTests` 使用生产入口及资源包的基准模板，校验 960、1920、3840 三种宽度下的实际选中按钮。它同时覆盖地表有楼层列、灰度地表模板和蓝色选中图标；列的存在不能代表当前地下层。

`BigMapCascadeMatcherTests` 校验完整视口的世界坐标中心、宽度、宽高比及楼层。预期中心/宽度固定记录在测试中，对照已知地图素材中的地形位置确定，坐标容差 20 游戏单位、尺寸容差 3%。城市地下层的素材为 `LayeredMap_29_-1`（Scale=3）。列车站素材的 Floor 与 UI 相对层序号不同：只用背景定位时不强行报告地表或某个未经确认的楼层。

测试依赖项目正常还原的 `BetterGI.Assets.Map` 地图与 QuickTeleport 模板，不需要游戏运行。冷启动分层搜索允许多帧推进；找到层后必须在后续平移帧继续匹配，不允许以 null 返回来跳过断言。

冷启动先用长边 512 的层图轮转搜索，整轮未命中后以长边 1536 补充细节；缓存按层和提取尺度区分，连续帧沿用成功时的尺度。`Match_HighZoomDetail_RetriesAtHigherResolution` 从矿区素材裁出高度放大的局部，单独验证小图未命中后能回退到高分辨率；它只固定按钮先验，实际几何和外观核验保持不变。

分层外观测试专门验证共享地表背景的误报：城市第一层不能被矿区背景代替，城市第二层不能被第一层背景代替。仅占截图小部分的第二层使用层图实际可见范围检查内点分布，随后仍需通过灰度外观核验。

外观核验必须先把素材对齐到截图尺度，再以同一尺度平滑，以抑制动态文字和传送图标。矿区失败样本在旧算法中几何匹配成功，外观相关度却只有约 0.69；修复后约 0.79，继续使用相关度至少 0.75、灰度差不超过 30 的门槛，并保持错误层拒绝用例。

五级全部接入生产匹配器：L1 读取缩放滑块并提供比例约束，L2 读取选中层并控制层候选/楼层确认，L3 用离线或本地传送锚点独立定位，L4 地表 SIFT，L5 分层 SIFT。L1/L2 是有真实消费者的定位约束，不把 UI 读数冒充绝对坐标。L3/L4/L5 并行开始，L4/L5 共享同一份截图特征；选出有效结果后取消其它分支，地下结果仍优先等待 L5 的楼层确认。

`BigMapZoomTests` 校验 960/1920/3840 的真实滑块读数，以及近、中、远视口均落在冷启动比例范围内。1080P 滑块中心 468～612 对应现有传送模块的 1～6 等级，默认一级比例以真实最大放大视口验证；匹配成功后继续用视口校准。未知缩放不会虚构精确比例。

`BigMapAnchorMatcherTests` 直接运行图标模板匹配和离线锚点几何，不调用 SIFT；稻妻真实视口必须定位成功，而锚点数据尚未覆盖的矿区必须拒绝。`BigMapAnchorGeometryTests` 独立验证缩放约束、外点、至少四个独立且非共线的锚点、多数一致性及竞争解拒绝，覆盖重复地标、镜像、旋转、共线和重复检测。两点只用于提出待验证的假设，不能直接返回成功。

端到端测试验证 L3 优先返回、连续缩放更新 L1 校准、L2 地下信号禁止把锚点平面定位误报成地表，以及近/远缩放锚点不足时仍由 L4 成功定位。调试信息在成功和失败时均显示实际执行阶段、分层搜索游标和外观拒绝原因。

几何测试另行构造已知变换，覆盖异常对应点、旋转、镜像、非等比缩放、点聚集、退化及非有限坐标；单位换算独立覆盖 Scale=1.5/2/3 与不同特征缩小比例。

`BigMapUiLayoutTests` 覆盖 960/1920/3840 下的详情和标记面板边界，以及浅色地形负例。SIFT、L3 图标和外观核验共享可见地图范围，保留完整截图尺寸；连续帧回归覆盖弹框开关及近、中、远缩放。楼层外观核验还必须看到足够的亮色层主体，不能仅凭暗色公共背景确认层名。

L5 冷启动通过进程共享的 256 像素分层地形索引提出候选，再用原有独立几何及外观核验确认。粗检索不会直接输出坐标，也不会将派生特征写入外部地图资源目录；粗检索漏检时仍保留跨帧轮转及高分辨率回退。

L3 的离线传送点表目前没有用户失败视口中的锚点坐标：运行图实际检测到 16 个锚点，不能将其笼统记成“锚点不足”。高置信度 L4/L5 确认的视口会采集独立图标坐标，写入运行目录的 `User/MapCache/big-map-anchors-v1.json`，用于后续 L3 独立匹配；不从 L3 自己或未确认的背景结果反向学习。测试使用隔离临时目录验证持久化，重建 L3 后仅凭锚点返回坐标；清空层候选的回归还验证地图会话重置不丢本地参考。连续地下帧也执行 L3，再由 L5 验证当前层名。

`BigMapParallelStagesTests` 通过任务门验证三个分支同时进入、地下楼层优先、胜出后的取消回收、外部取消后重试以及单分支异常隔离。真实 4K 截图另测处理中取消后继续定位另一张地图，保证输入生命周期正确。

`BigMapFrameTrackerTests` 验证实际平移、缩放及面板变化会使旧帧失效，静止截图、底部日志和小图标动画不会反复重启计算，缓慢移动能够累计到检测阈值。捕获线程检测变化即取消旧帧，在约 120ms 稳定后提交最新截图；每帧预算 10 秒，原生近邻检索按 128 个描述子分批并在批间取消，分层索引按层取消。OpenCV 单次原生调用在返回后响应取消，不在执行期间强行释放 Mat。worker 在 finally 恢复运行标记，发布前同时校验地图会话与视口修订号。
